# 美术设计

## 为什么要有这一步

副导演（ad-asset-bible）只写戏需要的东西加一个参照物，没来源不补知识。
有的图片模型会自己补出没写的细节，H3 这类扩散模型不会 —— 写什么画什么，没写的就空着。
直接把需求翻成提示词，餐厅只有一张桌子几把椅子、墙上什么都没有，手术室一张床一台机器。
所以**写提示词的人得先把它设计出来**：地方、人的造型、道具、特效都一样，"富太太常服""一张古琴""一道金色光索"到底长什么样，要有人设计。

## 方向

资产图不是一个镜头，是下游反复拿来当参考的定稿（换机位、编辑出图、贴进视频提示词）。设计要做到：

- **可信**：真去过这种地方、真见过这种人这种东西的人看了不出戏
- **完整**：按它的用途该有的都在，不只是需求里点名的那几件
- **是这部戏的这一个**：同样是手术室，顶级医院和县医院、新楼和老楼、刚做完大手术和正在准备，长得不一样；
  同样是富太太，什么出身、在家还是出门、今天见谁，穿得不一样。从故事出发设计，不画通用样板

设计靠你自己的判断，本 skill 不提供物件清单 —— 清单写死了，每次出来都大同小异。三条通用原则：

- **按身份和档次定讲究程度**：谁的、什么地位、多有钱，决定用料、做工、陈设繁简。有钱和有身份是两回事（有钱没身份的，形制寻常而用料贵）。
- **别出现不属于那个年代的东西**：器物、面料、款式、电器都对上全剧坐标里的年代地域。
- **写成看得见的样子**：不写专门术语（"乌头门""襦裙"这类模型不认识的词），不写否定句（"不用斗栱"，模型画不出"没有"），
  也不写评语（"高档""温馨"），都翻成看得见的材料、形状、做工。

## 第一步：全剧坐标（每部戏写一次）

| 坐标 | 写什么 | 例 |
|---|---|---|
| 成像方式 | 写实真人、3D 动画、二次元、定格、水墨…… | 写实真人短剧 |
| 时代地域 | 具体到能画：哪个国家地区、哪个年代、城乡、阶层分布。不写"古代""未来""架空"这类画不出来的词 | 当代中国一线城市，2020 年代 |
| 题材 | 赛博、武侠、仙侠、恐怖、废土……叠在时代地域之上，改变能源、材质、改装程度 | 都市奇幻：现实世界照常，超自然只体现在人和特效上 |

副导演的 `meta.worldview` 是起点；没写的从剧本推一个最合理的。全剧坐标写**一次**，放在出图单 JSON 的保留键 `"_design"` 里，
不在每条提示词里重抄（提示词里只写这张图用得上的那几句）。同一栋建筑、同一个院子的共用约定（建材、色调、装修风格）、特效语言也写在这里 ——
看不见彼此的区域（同一家医院的手术室和病房、楼上楼下）靠这里的约定保持一致。

成像方式大多只改"怎么画"（写进提示词的质感那句）；少数会改"画什么"：像素、剪纸、低多边形要减少物件、只留认得出的大件；
皮克斯式的陈设服从角色的主形状；定格动画的物件像手工缩微模型。

## 第二步：设计

共同的一条：**以戏为中心往外设计**（EV 2026-11-14 定）—— 先找这份资产在戏里怎么被用，把那一处设计具体，再往外丰富。
副导演给的参照物、认得出的那一处必须保留。

### 场景

中心是这场戏要用的东西或要发生的地方：戏里有人坐公园长椅，中心就是那张长椅；边走边打电话，中心就是那段步道。
先把中心设计具体（在这个地方的什么位置、什么样、紧挨着它的周围有什么），再往外丰富整个地方。想清楚这几件事：

1. **什么地方、什么档次**：放进全剧坐标里，它是哪一类、新还是旧、贵还是寒酸
2. **谁在用、用了多久**：陈设由使用者和用途决定
3. **按用途该有什么**：功能上必须有的设施和大件写全，再是置景小物（墙上挂的、台面上放的、角落里堆的）
4. **这场戏时是什么状态**：饭前饭后、手术前后、刚打扫还是一片狼藉
5. **谁在维护、管得多严**：顶级医院的手术室抢救完，医疗废物也进污物桶、利器盒，不扔在地上；有人天天打扫的公园，坏砖会修。
   痕迹多少跟着维护水平走，不跟着"要显得真实"走
6. **痕迹**：在维护水平允许的范围内，磨损脏污按使用逻辑出现（门把手、常走的路、灶台边），新旧并存。
   **痕迹是轻的、整体的**（"用了几年，有正常使用的磨损"），不是一处处点名的破损
7. **不规则**：同类东西有差异，不排成列队，有挪动、随手放的东西。不规则 ≠ 破损。
   地面也一样：大面积同一种铺地（卵石、碎石、沙地、一色的地砖）画出来是一整片重复的纹理，
   大块地面要分区（几种铺装、草地、树影、花木把它打断），或者让它在画面里占得少
8. **尺度**：用东西互相比（"矮墙只到空调外机的一半高"），不只写数字或"齐腰高"。
   **档次要落到规模上**：豪宅、宫殿、大堂的气派主要靠大，只写样式会画成一个小院子加一栋孤零零的小楼。
   写清这地方比人、比车大多少（前庭能并排停几辆车、楼有几层、正面多宽、有没有附楼），四周的地盘也要跟这个档次相称
9. **画面里有某人形象的场景**（遗照、雕像）：主资产设计成空着的样子（空的黑色相框、看不清脸的雕像），
   形象放在那个变体的设计里
10. **衍生区域**（盘点里 `basedOn` 的那几块：开放式的客厅、餐厅、厨房）：主区域全景的设计要把它们都放进去、看得见；
   衍生区域的设计就是全景里那一块的近景，材质、家具、灯跟全景对得上。看不见的房间不用 `basedOn`，靠 `_design` 里的共用约定
11. **纵深和边界**：门外、窗外、走廊尽头是什么，写出来，不能是一片黑或一片白
12. **光**：此刻真实存在哪些光源、从哪来

**不要的默认画面**：空荡的样板间、室内设计效果图、家具摆得像展厅、物件排成阵列、对称居中、门窗外一片漆黑、崭新无痕。
**也别矫枉过正**：为了"真实"点名写破损脏乱，出来的是刻意的破败（抢救后"地上散着带血纱布"像事故现场）。
破损脏乱只在剧情需要时写（战后废墟、荒废多年的屋子），平时只写整体的使用程度。
"没有人"只写没有人（资产图要空场景），不写成"空荡、光秃"。

### 角色造型

设计单元是**一个人的一套造型**（副导演的一份服装资产）和它的状态变体。中心是**这个人此刻是谁**：身份、阶层、年龄、职业、处境，
这场戏在什么场合、要干什么。衣服是这个人生活出来的结果，不是戏服店借来的。

1. **这身行头从哪来**：买的、定做的、单位发的、借的、传下来的；什么档次（不写品牌名，写看得见的做工和料子）
2. **全身都要设计**：衣服、鞋、发型、妆、首饰、包、眼镜、手（指甲、戒指）
3. **怎么穿**：合不合身、怎么搭、领口袖口扣子、穿了多久。由场合和习惯决定，写成看得见的样子，不写性格词
4. **时代地域与形制**：古装按朝代和身份等级，不是一律仙气飘飘；现代按这个城市这个阶层真实的穿法，不是富人一律西装晚礼服；架空按题材改材料和改装
5. **痕迹跟着维护走**：有人打理的衣服平整干净，干活的人衣服洗旧、膝盖肘部先磨。轻的、整体的，不点名破洞
6. **同一个人的几套之间**：看得出是同一个人（身形、发型、某件常戴的东西延续），不硬加统一元素
7. **状态变体写到全身**：受伤、战后、施法、淋雨、刚睡醒 —— 脸、头发、手、鞋、头饰、衣服各是什么样，而且有来由（哪边先湿、血从哪来、尘土积在哪）。
   只写"袍子沾满尘土"，出来衣服脏了，脸和手还是干净的
8. **长相**（角色底档，不单独出图，写进这个角色第一套服装的提示词）：年龄、脸型、发型、身形像这个身份这个年纪的真人，不是统一的网红脸。
   **按选角的标准定好不好看**：主角和戏里设定为好看的人，按主演的标准长得好看、上镜；真实感靠肤质和神态，不靠把长相写普通。
   人设的气质（女君的清冷威严、霸总的压迫感）落到看得见的眉眼、骨相和眼神上，不写成性格词。
   好看的人**不写往普通拉的特征**（"颧骨不高""嘴唇偏薄""不是网红脸"）—— 第五遍的女主就是这么被写成路人的，拔掉官方 skill 后的验证又犯了一次。**辨识点只用剧本给的**（纹身、疤、痣、胎记），剧本没写不编

**不要的默认画面**：影楼写真、戏服店、cosplay；全新熨平没穿过；所有角色一个审美模板；古装一律白纱飘飘。没有剧情需要，也不写破旧邋遢。

### 道具

中心是**这件东西在戏里怎么被用**：谁拿着、弹、递、摔、藏。

1. **是什么、哪来的**：年代、产地、做工档次；传家的、买的、定做的、捡的
2. **材料和做工**：看得见的材料、结构、工艺细节
3. **谁的、用了多久、怎么保养**：一件传了几代的老物件和刚买回家的不一样
4. **尺度**：跟手、跟人身体比多大
5. **认得出的那一处**：副导演给的那个特征保留，写具体
6. **状态变体还是这一件**：碎了、烧了、发光了，形状和那一处特征不变

**不要的默认画面**：博物馆展品、电商新品、游戏道具图标感。

### 特效

**先定这部戏的特效语言**（每部戏一次，写进 `"_design"`）：这股力量是什么（灵力、科技、魔法、诅咒），由此定颜色、质感（光、雾、丝、粒子、流体、实体）、
亮度和边缘。同一个人、同一个体系的特效都从这套语言里出，彼此靠形态区分，不是每个特效换一套颜色。

每个特效再设计：**形态**（什么形状、跟人比多大、由什么构成）/ **颜色和亮度分布**（哪里最亮、往外怎么变淡）/
**认得出的那一处** / **跟环境的关系**（照亮周围什么、在灰底上投下什么光）。只写它**静止那一刻**长什么样；从哪发出、怎么动、多快，是视频提示词的事。

**不要的默认画面**：游戏技能特效、霓虹灯管、满屏粒子、每个特效一种颜色。

## 第三步：直接写成提示词

设计想清楚了就直接写成中文提示词，不另交设计稿 —— 设计的结果就是提示词。（EV 2026-11-17 定：原来设计稿、提示词分两步，
后一步只是把设计翻译一遍；实测设计原文直接喂 H3，跟翻译后的提示词同一档，见仓库 README 的「拔掉官方 skill」。）

**写什么**（设计的部分）：

- **中心写具体**：场景是戏用的那个东西或那块区域（在哪、什么样、紧挨着它的周围有什么）；角色是这套造型从头到脚；
  道具是这件东西本身和认得出的那一处；特效是它的形态和那一处特征
- **外围只说有什么**：其余的设施、大件、置景小物各是什么样（材质、款式、新旧）。**给规则，不给画面**（EV 2026-11-14 定）：
  不定数量、不排逐件位置、不点名哪一件坏了歪了 —— 写得越细，模型越把它当主角去堆（写"四张长椅、两张挨着"，出来五张一模一样排成一列）。
  戏里要求确定数量的（两个人对坐、三炷香）照写
- **按什么规则摆、处在什么状态**：布局原则（像真实的这种地方那样随意、有疏有密）、维护和使用程度、此刻的状态和光

必须在画面里认得出来的，只有中心和副导演给的参照物。副导演需求里点名的痕迹（"裙摆沾着几处灰印"）不是参照物，按上面的痕迹规则写成整体程度。不写"为什么"，不堆形容词，不留占位符（`TODO`、方括号、"待填"，build 会拦）。

**怎么写**（五条写法，来自 MiniMax 官方的 H3 提示词指南）：

1. **先说这是什么图，再布局，再细节**：开头一句说这张图是什么（三张棚拍照片拼成的角色定妆照、一个地方的全景、一件道具的产品照），
   接着说画面怎么分、东西在哪、从哪看，最后才是材料、做工、光
2. **风格写成看得见的**：颜色、材料、光、质感，不写"高级""温馨""电影感"这类评语
3. **字**：画面里必须有的字（门上"手术中"的灯箱、招牌上的店名）用引号写全、写在哪；其余一律在结尾声明
   "画面里没有任何文字、字母或数字。" —— 不声明，H3 会自己编招牌、标签，中文的氛围词还会被整句画成字
4. **参考图按 `<Picture 1>`、`<Picture 2>` 点名**：每张说清提供什么、哪些不用；要保留的人或物定义成 `<Subject 1>`，
   说它是全部保留还是部分保留、保留哪些
5. **编辑写最终的样子**：写成"画面里她穿着……"，不写"把衣服换成……"；改了什么、改到哪、什么不变，都说清楚

四类资产的固定格式（画幅、版面、背景、光、有没有人）、同一资产多张图怎么用参考图、尺寸，
按 [references/asset-prompts.md](references/asset-prompts.md) 写。**写之前先读它。**

## 第四步：交出图单，出图

按 tag 交一份出图单 JSON：

```json
{
  "_design": "全剧坐标、同一栋建筑的共用约定、特效语言",
  "_note": "整份出图单的通用说明，给手动出图的人看",
  "@char_lin_tshirt": { "prompt": "…", "size": "5472x3072" },
  "@char_lin_suit": { "prompt": "<Picture 1>三格里的男人是<Subject 1>。……", "size": "4000x2240", "refImage": ["@char_lin_tshirt"] }
}
```

挂在：场景和场景变体；每份服装（底档的长相写进这个角色第一套服装的提示词，底档自己不出图）、服装的状态变体；道具和它的变体；特效和它的变体。
由副导演的 `scripts/attach-plan.mjs` 合进页面的「提示词」页，`_design` 显示在页顶（见仓库根目录 `PIPELINE.md`）。
`size`、`refImage`、`_note` 怎么填见 `references/asset-prompts.md`。

出不出图看用户有没有通道，不要假设用户有哪台机器：

- **ComfyUI**（装了 H3-Image 的模型；本机要有 node 18+、ffmpeg 和 ffprobe）：用 `scripts/render-comfyui.mjs`，**分两段，中间让用户挑图**
  （EV 2026-11-15 定：编辑图都拿文生图当参考，底图不对，后面全白出）：
  1. `--stage t2i`：只出文生图，每张出 4 个候选（`--n` 改个数），生成 `<图片目录>/候选/挑图.html`。**出完停下**
  2. 把 `<图片目录>/候选/挑图.html` 的路径给用户，**停下等**。用户双击打开、每个资产选一张，点「复制选择」回对话粘贴
     （一行一个 `<tag> <第几张>`；用户直接说"公园选 3"也行）。把那段文字原样交给 `--pick "<文字>"`，选中的拷成正式的图。
     0 = 都不要：旧候选挪进 `候选/弃用/`。用户点了重抽会顺手写意见（复制出来是 `<tag> 0 意见：…`，记进 `候选/意见.jsonl`）。
     **有意见先改再抽**：设计没想到的改设计，想到了没画出来的改写法；光换种子，出来还是差不多。没写意见就问一句哪里不满意，
     用户说就是运气不好再只换种子。改完换个 `--seed` 再跑第 1 步，只补出那几个，再让用户挑一次
  3. `--stage edit`：出所有带参考图的，都拿选中的那张当参考，每张出一个

  按依赖顺序出、参考图自动缩到约 4MP、已出的跳过（断了重跑接着出）；模型文件名不同就加 `--unet / --clip / --vae`。
  编辑图单张重出：删掉那张，加 `--only <tag> --seed <新种子>` 再跑 `--stage edit`。
  工作流文件和模型下载见 [comfyui/README.md](comfyui/README.md)
- **没有**：停在出图单。用户打开网页的「提示词」页，按顺序复制、自己出图、把图拖回卡片

**不设审稿，也不自查**：写完直接出图，人看图提问题。人指出问题时先判断：
是设计没想到（改设计），还是想到了但模型没画出来（改写法、换种子）。
