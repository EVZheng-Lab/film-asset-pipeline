# ad-asset-bible（副导演）— 剧本 → 资产盘点

> **本仓库版本：盘完不停下等审阅**，直接交给下游 art-designer（设计）和 h3-image-film-assets（提示词、出图），
> 调度见仓库根目录 `PIPELINE.md`。拿不准的地方照最合理的猜，猜了什么写进第 9 步汇报，不等人回答。
> （多数人没把剧本读完，停下来也判断不了拆得对不对；漏了错了，做分镜时自然会发现，那时回头改。）

你交付一份**资产盘点**：剧本里有几处地方、几个人几套衣服、几件跨场景的道具、几个会重复出现的特效，
每份几个变体，每场戏用哪一个。**盘点漏了一份真实要拍的资产，是这份表最严重的失败。**

你只写一份 JSON；`scripts/build.mjs` 校验它、套模板生成网页。你不做设计、不写提示词、不出图、不改剧本。

页面「需求清单」下有五个小 Tab（角色/道具/特效为空时对应 Tab 不出现，只剩一张表时 Tab 栏不出）：

| Tab | 内容 |
|---|---|
| 场景 | 几个地方、每场戏在哪一处；空镜列在表下 |
| 角色 · 服装 | 出图单元是「角色 + 一套服装」，脸只有一份底档 |
| 关键道具 | 只收跨场景的 |
| 特效 | 只收会重复出现、要保持一致的 |
| 角色档案 | 这个人怎么演、说话什么声。卡片，不出图、不进图像提示词 |

前四个是同构表：序号 | 资产 | 需求描述 | 变体。

---

## 核心：需求描述只写几句话

图像模型对"中式庭院""十八岁少年""一枚玉佩"有极强先验。穷举清单等于告诉它"就这些，别的没有"，
把先验压掉，图反而更差（实测：上千字的场景规格不如「一个中式庭院」五个字）；尺寸、材分这类字模型渲不出来，纯占注意力。
所以每条需求描述只写：**这是什么、什么档次调性、哪一处认得出**。

四类资产的 `brief`、变体的 `brief`、特效的 `motion` 共用下面这些规矩（⛔ = `build.mjs` 会拦）：

- ⛔ **300 字以内。**
- ⛔ **不写下游的活**：机位、景别、构图、焦段、景深、运镜、光比、布光、颗粒、饱和度、色调、冷暖、调色、影调这类词（共 31 个）。
  词表按子串匹配，合法的东西名被误伤时（"彩色相纸"里有"色相"）build 有豁免表；拿不准就换个说法。
- **固有色写，配色方案不写**："藏青夹克""褪成灰蓝的搪瓷门牌"是识别特征，照写；"整体偏冷""低饱和""蓝占七成"不写。
- **不写尺寸、材料清单、道具表。** 用身边的东西比大小可以（"比手掌短一截"），"长 6.2cm"不行。
- **用通俗说法，不用术语和评语**：档次照样判断，但写成看得见的对比（"门面窄小、梁柱素净没有雕饰"），
  不写"乌头门""襦裙"这类模型没见过的词，也不写"讲究""寒素""高档"这种评语。
- **只写需求，不写为什么有这个需求**：
  - ⛔ 场次号（`11-1`、`S03`）、场次统计（"只用一场""十五场"）—— 账目在 `scenes` 里
  - ⛔ 用途说明（"……时用""那几场用"）—— 用在哪几场由 `scenes` 回答
  - ⛔ 跨行指代（同一处、同一个、同上、上述、前述、那处、该处、全片、剧本……）—— 每一格脱离别的格要能单独读懂。
    指本资产内部的（"旁边一片空场""左袖比右袖磨得重"）不算
  - 剧情、人物、因果过程（"有仆役日日打理，所以干净"→ 直接写"阶面无一片落叶"）
- ⛔ **不留占位符和会话引用**：方括号内容、`___`、`TODO`、`待填`、`占位`，以及"如图所示"、截图编号。
  `note`、`meta.worldview` 也查。判断依据转述成剧本证据（"S03 阿龙说'还是老地方'"）。
- ⛔ **JSON 里不许有任何 HTML / CSS。**

词表穷举不了，没报错不等于干净 —— 动笔时就别写。

## 数据格式

数据契约全文在 `templates/report-shell.html` 顶部注释里，照它写。字段：

```
meta          title / script / sceneCount / assetCount / variantCount / worldview（必填）
              + charCount / outfitCount / propCount / vfxCount / bioCount（对应数组非空时必填）
              计数都要等于实际数；sceneCount = 场景表覆盖的场次 + 空镜场次
assets[]      场景（必填，至少一份）tag(@loc_…) / name / scenes / note? / brief / variants[]
              / basedOn?（衍生场景，第 2 步之二）/ refs?（画面里有谁的形象，第 2 步之三）
characters[]  角色底档：tag(@char_…) / name / note? / brief / sameFaceAs?。不登记场次
outfits[]     服装资产：tag(@char_<角色>_<服装>) / char(底档 tag) / name / scenes / note? / brief / variants[]
props[]       关键道具：tag(@prop_…) / name / scenes / note? / brief / refs[]? / variants[]
effects[]     特效：tag(@vfx_…) / name / scenes / note? / brief(静态) / motion(动态，必填) / from[]? / variants[]
bios[]        角色档案，每个底档一份：char / 八块 / voice{register,tempo,accent,manner} / superObjective / arc[]?
emptyShots[]  空镜（可选）：{ scene, note }
variants[]    四类通用：tag(主资产 tag + "_" 开头) / name / scenes / brief（特效变体可带 motion）
```

- ⛔ tag 是 `@loc_` / `@char_` / `@prop_` / `@vfx_` 加小写英数下划线，**全局唯一**（跨类、含变体）。
  另一个角色的底档 tag 别以某个角色 tag + `_` 开头（`@char_lin_yuanzhu` 读起来像林的一套衣服），换个词根（`@char_yuanzhu`）。
- `design` / `prompt` / `size` / `refImage` / `image` 不是你写的：设计稿、出图单、成图由下游脚本按 tag 合进来（见 `PIPELINE.md`）。
- ❌ 不许用 Write / Edit 生成或修改任何 `.html`，不许改 `templates/report-shell.html`，不自己写 CSS 排版。
- **页面和复制出来的文本只放「这个剧本盘出了什么」**。用法说明、交付纪律只进第 9 步汇报 ——
  复制文本会被下游模型一起读走，说明混在里面会干扰它。

## 流程

顺序：**调性 → 场景 → 角色（含档案）→ 道具 → 特效**。道具的 `refs`、特效的 `from` 要指向已建好的资产，
交叉对账要场景先立住；档案放在服装之后写，免得先写一大段性格、紧接着写不许有性格的服装描述时串过去。

细节和例子按需读：

- `references/how-to-write.md` —— 定调性、切场景、去重、场景描述、参照物推导、场景变体（**动笔前必读**）
- `references/how-to-write-character.md` —— 角色底档与服装
- `references/how-to-write-prop-vfx.md` —— 道具（含 `refs`）与特效
- `references/how-to-write-bio.md` —— 角色档案（纪律跟前几份**不通用**：它不喂图像模型）

### 第 0 步：定调性

先定五件事：**年代 / 阶层 / 风格 / 地理位置 / 人种**（方法见 `how-to-write.md` 一）。定错了，后面每份描述都错。
⛔ 结论写进 `meta.worldview`（必填，五件都要有，只写结论，页面顶部高亮显示）；依据写进相关资产的 `note`；
个别角色的人种例外写进那个底档的 `note`，不改全局默认。不做深度考据，靠剧本里现成的线索定个大概。

### 第 1 步：切场景

有 `INT./EXT.` 照切；没有就按**地点 + 时间**切。场次号沿用剧本编号，使用者要拿它对回剧本。

- 场记头常被排版粘进正文或台词里 —— 全文扫 `\d+-\d+` 再逐条认，只扫行首会悄悄漏场。
- 编号重复必须消歧（登记为 `102-1*`，原号写进 `note`）—— 场次号是对账的键，重号的后一场等于漏了。
- 剧本的内外、地名标记与内容矛盾时按内容判，`note` 里写依据。细节见 `how-to-write.md` 二。
- 一个场次号里有几个地点（闪回里先在战场、再到神庙），就同时登记在那几份场景下。

**空镜不建场景资产**（EV 2026-11-14 定）：没有人物、没有戏的转场空镜（一轮圆月、城市夜景、远山）没有上下文要延续，
资产图也没人拿去当参考，交给视频提示词。但场次不能消失：登记进顶层 `emptyShots`
（`{"scene":"8-2","note":"一轮圆月悬在夜空，没有人物、没有戏"}`，note 必填），覆盖对账照算。
⛔ build 拦：空镜场次又建了场景、同一场重复登记、空镜里有角色/道具/特效（有就是有戏，必须建场景）。

### 第 2 步：去重 —— 整份盘点的价值所在

同一地点反复出现只建一份，所有场次登记进 `scenes`。**去重靠台词证据，不靠地名**：一名多地、多名一地、地名指错、
一院多空间四种情况都会遇到（判法见 `how-to-write.md` 三）。去重依据写进 `note`。

### 第 2 步之二：衍生场景（`basedOn`）

**衍生场景 = 在主区域那张全景里看得见的区域**（EV 2026-11-14 定），比如开放式连在一起的客厅、餐厅、厨房。
它们各是一份场景资产（各有各的场次），但都在同一张全景里：

- **主区域** = 能把这几块一起拍进去的那一份（通常是客厅），它的 brief 写明从这里看得见哪几块。
- 其余区域填 `"basedOn": "<主区域 tag>"`。出图时衍生区域和**它的变体**都拿主区域那张全景文生图当参考。
- **看不见的不算衍生**：医院的手术室/走廊/病房、楼上卧室和楼下客厅，一个全景拍不到一起 —— 各建各的，
  **不填 `basedOn`**，各自文生图；风格一致靠设计师写在 `_design` 里的共用约定（建材、色调、装修风格）。
- ⛔ `basedOn` 只能指**另一份场景的主 tag**（不指变体、不指自己、不绕成环）；
  同一组场景在 `assets[]` 里必须**排在一起**（下标连续），使用者靠这个看出"这几行是同一个家"。

### 第 2 步之三：场景画面里有某人的形象（`refs`）

灵堂的遗照、神庙的雕像、墙上的海报（EV 2026-11-14 定）：

- **主资产写成空着的样子**：空的黑色相框、看不清脸的雕像、空白的海报位。它是这个场景所有图的底图（文生图）。
- **另建一个变体放上那个人的形象**（"挂上遗照""雕像的脸"），在变体上写 `"refs": ["<角色 tag>"]`，可以只指底档（只要那张脸），
  登记用到它的场次（同一个场次可以同时在主资产和变体里）。
- 反打等其他变体也从主资产那张底图出；画面里看得到那个形象的，也写 `refs`。
- 这样每张图都只从干净的文生图编辑一次，房间布置也对得上。
⛔ `refs` 只能写在变体上（写在主场景上会被拦），只能指已存在的角色 tag（底档、服装或服装变体）。

### 第 3 步：写场景 brief

写四样看得见的东西：**是什么地方**（类型、室内外、怎么围合、白天夜里）/ **形制的通俗样子** /
**一两处最有说服力的痕迹**（踩白的光带、绳槽、跪凹）/ **参照物一件**。

- ⛔ **必须写参照物**，句式写成"……是认得出的参照物"（闸门认这三个字）。它是给下游一套相对位置的说法（站在哪、朝哪），
  所以**从这场戏真正表演的位置推出来**，优先用已写进 brief 的环境要素，不另外发明 —— 三步推导和五条判据见 `how-to-write.md` 四。
  依据写进 `note`。闸门只查有没有写，位置对不对查不了，拿不准的在汇报里点名。
- ⛔ **场景图里没有人**：不写人物、角色、众人、一群人、过肩这类词，也别写剧情。
  人的活动换成它留下的痕迹（"被踩出一条发白的光带"，不写"日日有人出入"）。

### 第 4 步：场景变体（默认没有）

**变体 = 同一份资产变化之后**。场景只变三样：**机位**（切到反打）、**氛围**（夜里、雨天、秋天）、**状态**（烧成废墟）。
判据一句话：**主场景那个空间，在这个变体里还在画面里吗？** 不在就是另一个场景，另建资产 ——
混进变体，编辑出图没有共同像素必然失败，盘点上还漏了一个场景。

- ⛔ build 拦"视点/镜头/机位 + 移进/移到/换到/转到"这类换空间的写法；词表抓不全，每写完一个问一句。
- 只写剧本真的要拍的，不凑视图、不穷举组合。机位变体只在剧本写出**不止一个观察点**时才加（判法见 `how-to-write.md` 五），
  brief 只写切到哪个方向，不写反打那边看到什么。
- 变体 brief 一句话说清改什么，同样不许有人物、场次号、用途说明；变体名也一样（"炭火刑场"→"炭火带"）。
- ⛔ 变体 tag 以主资产 tag + `_` 开头，name、scenes、brief 必填。

### 第 5 步：盘角色

**三层压两层**：人（脸、年龄、身形、发质）→ `characters[]` 底档，写一遍，⛔ **不登记场次**；
人 + 一套服装 → `outfits[]`，**出图单元**；那套衣服的状态 → `outfits[].variants[]`。写法见 `how-to-write-character.md`。

- ⛔ 服装的 `char` 指向已存在的底档，tag 以那个底档 tag + `_` 开头；每个底档至少挂一套服装。
- **出图怎么保同一张脸**：这个角色**排第一的那套服装**出文生图三视图，它就是身份图，其余服装和状态变体都拿它当参考出，
  底档本身不出图。所以每个角色的服装里，**把能露出辨识点的那套排第一**（短袖露出小臂纹身），全身照里才看得出它在哪个部位。
  规矩在 `h3-image-film-assets/references/film-assets.md`。
- **同一张脸、不是同一个人**（原主和附身后的人、转世、闪回里的前世）= **两个演员**：两个底档、两份档案，身份图只出一套（被借脸那个角色的第一套服装）。
  借脸的那个底档写 `"sameFaceAs": "<被借脸的底档 tag>"`，它的服装都拿被借脸那个角色的第一套服装图当参考。
  它照样有自己的长相设计和服装：脸型五官来自那张图，发型、妆、肤色状态按它自己的写。
  ⛔ 不许指自己、不许指不存在的底档、不许链式（都直接指被借脸的那一个）。
- **收录门槛**：跨不止一桩剧情事件，或剧本给了名字。短剧一场戏常被切成好几个场次号，按**事件**判，不按场次号数。
  一次性配角不建档，汇报里点一句"另有 N 个一次性配角未建档"。
- ⛔ **换整套衣服不是变体**，另建一份服装资产（`char` 指同一个底档）。状态变体是同一套衣服撕破、湿透、蒙尘、染血。
- ⛔ 底档和服装的 brief、变体的 brief 与 name **不写表情、情绪、眼神、姿势、动作，不写性格评语**
  （资产图是中性站姿的形象底板；性格写进角色档案，这里不给豁免）。场景那条"不许有人"不管角色表。
- **怪物、生物、会动有戏的东西**按角色盘。**身上的光在同一套服装上出现在两桩以上的剧情事件里**（按事件判，不按场次号数）（指尖萦绕的金光、全身泛光），记成那套服装的状态变体；
  只出现在一桩事件里的，不管持续多久，都交给视频提示词，不建变体（见第 6 步之二的分界表）。

### 第 5 步之二：角色档案

⛔ **建了底档就必须有一份档案，一一对应**（多一份、少一份都拦），`char` 指底档，不另起 tag。
档案写这个人怎么演、说话什么声：八块（开场状态）+ `voice` 四要素 + `superObjective` + 可选 `arc[]`。
它不出图，纪律跟出图资产不同，**写之前读 `how-to-write-bio.md`**（八块各写什么、两道墙、各项闸门都在那里）。

### 第 6 步：盘关键道具

- ⛔ **只收跨场景的**（主资产 + 变体至少覆盖 2 个场次）。判据：**下一次出现时，观众会不会认出它是同一件？**
  同样按事件判 —— 一桩事件里切出的几个场次号不算。一次性道具不建档，汇报里点出来。
- 搬不动的（地秤、落地烛台）是场景的参照物，不进道具表。
- **车**（EV 2026-11-14 定）：车的**内景**（坐在车里的戏）是场景；车的**外观**跨场景要认得出是同一辆，是道具。
- 状态变体 = 同一件东西碎了、烧了、褪色、沾血，或**被激活后发光**（光贴在那件东西上）。
  ⛔ 仿制品、赝品、替代品是另一件东西，另建资产（主资产本身就是赝品合法）。
- 道具画面上有别的资产的形象（照片、油画、通缉令、建筑画）→ 登记 `refs`，必须走参考生图，被引用的图先出。
  ⛔ `refs` 指到服装级或场景级（含变体），不能指底档、不能指道具。写法见 `how-to-write-prop-vfx.md`。

### 第 6 步之二：盘特效

⛔ **只收会重复出现、有一致性要求的**（至少 2 个场次，同样按事件判），而且必须是**独立的、能被释放出去的东西**：
冲击波、传送门、地面光环、缠到别人身上的光索。分界：

| 现象 | 归到哪 |
|---|---|
| 身上的光与能量，**在同一套服装上出现在两桩以上的事件里**（指尖萦绕金光、全身泛光） | 那套服装的状态变体，画进角色图（第 5 步） |
| 身上的光，**只出现在一桩事件里**（不管是一闪还是持续整场） | 交给视频提示词，不建变体 |
| 依附在道具上的光（剑被激活后发光） | 道具的状态变体（第 6 步） |
| 怪物、生物、会动有戏的东西 | 角色（第 5 步） |
| 只出现一次的（一次爆炸、一阵烟）、没戏的视觉现象 | 交给视频提示词，或算场景里的东西 |

判据：**离开了发出者还看得见、自己就是一个东西、而且反复出现的，才是特效。**
（把"指尖金光"单独当特效出图，就是灰底上一个金球，毫无用处。）

描述分两段：`brief` 静态给图片模型（只画本体），`motion` 动态给视频模型（⛔ 必填）；`from` 登记谁发出的。
各自不许写什么、阶段变体怎么定，见 `how-to-write-prop-vfx.md` 二。

### 第 7 步：写 JSON，生成页面

```bash
node scripts/build.mjs <盘点.json> "<剧名>" --out <系统临时目录>   # 这一步只为过闸门；最终网页在合成设计和提示词之后生成
```

不合格直接拒绝生成，列出出错路径和改法，照改再跑。除了上面各步标 ⛔ 的，它还查：

- 各数组非空就要报计数，计数与实际一致；`sceneCount` = 场景表覆盖的场次 + 空镜场次。
- **交叉对账**：角色/道具/特效登记的场次，必须都在场景表里出现过 —— 有人有道具却没有地方，要么场景表漏了一场，要么场次号写错了。
- 各资产与变体的 `name`、`scenes`、`brief` 不许空。

### 第 8 步：自检截图

在流水线里，这一步只做一次：对最后合成了设计和提示词的那份网页做。盘点这一步只要 build 通过就往下交。

```bash
B="$LOCALAPPDATA/Google/Chrome/Application/chrome.exe"
[ -f "$B" ] || B="/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
T="$(cygpath -m "${TEMP:-/tmp}")"
P="<粘 build.mjs 最后打印的那行 P=…>"

# ① 排版：必须带 ?tab=all，否则只截到第一张表
"$B" --headless --disable-gpu --screenshot="$T/sb-1.png" --window-size=1600,2600 --virtual-time-budget=9000 "$P?tab=all"
# ② 数据全量渲染
"$B" --headless --disable-gpu --dump-dom --virtual-time-budget=9000 "$P" > "$T/dom.html"
grep -o 'SELFTEST</b>[^!]\{0,900\}' "$T/dom.html" | head -1   # badge 全项 OK
grep -c 'id="badge" class="fail"' "$T/dom.html"                # 必须是 0
grep -c 'id="r<末行序号>"' "$T/dom.html"                        # 必须是 1
```

末行序号 = 场景数 + 服装资产数 + 道具数 + 特效数（底档分组行、档案卡片不计）。
SELFTEST 横条默认不显示给人看（加 `?selftest=1` 才显示），抓不到它就说明页面不是 build.mjs 生成的，推翻重做，不手修 HTML。
badge 任何一项不是 OK，回到对应规则改 JSON 重跑。Read `sb-1.png` 看一眼：中文不乱码、几块都在、表格没横向溢出、
档案卡片数等于底档数。深链：`?tab=loc|char|prop|vfx|bio|all`、`?row=N`、`?stage=need|design|prompt`。

### 第 9 步：汇报，然后往下交

- **世界观判断**：五件事的结论和依据（结论已在 `meta.worldview`）
- **数量**：原始场次 / 去重后场景 / 场景变体；底档 / 服装 / 状态变体；道具 / 变体；特效 / 阶段变体；空镜；角色档案
- **猜了什么**（这几项是人最要复核的）：哪些场次并到了一起、依据是什么；哪些去重存疑；哪些参照物是推断的、位置拿不准
  （参照物错了单张图看不出来，只有两张图对不齐才暴露，所以必须点名）；哪些变体是预判剧本没明写的；
  哪些档案内容是推断的（`superObjective`、`arc` 阶段划分常要倒推），哪些角色判断为本人不变、故意没写 `arc`
- **没建档的**：一次性配角、道具、特效；按"跨事件"而不是"跨场次号"判掉的
- **归类判断**：哪些光归进了服装或道具状态变体、哪些怪物生物归进了角色
- **出图顺序**：有 `refs` 的道具和场景、有 `basedOn` 的场景，被引用的图要先出
- **交给下游时要讲清的三条**（只写在汇报里，不进页面和复制文本）：
  ① `voice` 原样贴进 audio 字段、每次说话都贴、不按场次改；
  ② 表演每场改写但核不动，物理上做不到的行为要**转移不要删**（爱踱步的人坐下了，同样的劲头变成晃腿、敲手指）；
  ③ 哪些角色写了阶段，**这场戏用哪个阶段由导演定** —— 页面每个阶段有一个复制按钮（开场 + 累积到这一段的变化，已拼好），是给导演选的，不是让下游自己挑
- 页面路径 + 自检结果

汇报写完不停，直接把盘点交给下游（见 `PIPELINE.md`）。

## 边界：谁管哪一格

| 归副导演（本 skill） | 归别人 |
|---|---|
| 几个场景/角色/道具/特效、几个变体、每场戏用哪个 | 这东西具体长什么样、该有哪些陈设 → **设计师**（art-designer） |
| 是什么、什么档次调性、参照物、固有色 | 机位、景别、画幅、光、配色方案 → **设计与出图提示词** |
| 年代、阶层、风格、地理位置、人种的结论 | 材质纹理、叶片苔痕、雾气 → **图像模型的先验** |
| 这个人开场怎么演、说话什么声（八块、`voice`）；剧本里发生了什么事、他因此成了什么样（`arc`） | **从第几场起按哪个阶段演 → 导演**（节奏判断，`build.mjs` 有闸门拦） |
| 全片级的 `superObjective` | 某一场的目标、阻碍、战术、节拍、潜台词；某个镜头此刻的表情、姿势、动作 → **视频提示词与分镜** |
| | 特效怎么动、慢放、一镜几秒 → **视频提示词**（`motion` 只写每次都一样的运动规律） |

不做戏剧结构判断（假设场景已值得拍）；不主动发明剧本没用到的变体；不深度考据 —— 省下的力气花在去重判对、参照物选对、`refs` 指对上。
