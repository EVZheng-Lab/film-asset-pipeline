# 影视资产出图标准（film assets）

> 本文件是新增的，不是 MiniMax 原版内容。出图样式的标准移植自 lira-EV
> （EV 个人版 Lira，Higgsfield 官方 Lira skill 的改版），特效一类是新补的。
> 官方 SKILL.md 与 `t2i-en.txt` 的写作规则全部照常适用；本文件只额外规定
> **影视资产图的固定出图格式**：画幅、构图、背景、光、有没有人，以及同一资产多张图怎么用参考图。

## 什么时候用

需求是一份**影视制作资产**：角色（一个人穿一套服装）、场景、道具、特效。典型来源是 ad-asset-bible（副导演）的盘点，
经 art-designer 设计过的设计说明。**有设计说明就按设计说明写提示词**，不直接拿盘点的需求描述写 ——
H3 写什么画什么、不会自己补陈设，直接翻需求只会出空荡的样板间。

资产图**不是一个镜头**，是下游反复拿来当参考的定稿（参考生图、编辑换机位、贴进视频提示词），所以样式固定：
官方规则里"自己选画幅、自己定构图"的部分，对这四类资产**以本文件为准**；其余规则（任务先于风格、用看得见的细节写风格、无文字声明、最终检查）不变。

## 四类资产的固定格式

### 1. 角色 —— 三视图

| 项 | 规定 |
|---|---|
| 画幅 | 16:9（16MP：5472x3072） |
| 版面 | 三张并排的棚拍照片：**左** 全身正面、从头到脚；**中** 全身背面、带头；**右** 3/4 侧面头肩特写，脸和身体转约 45°，眼睛直视镜头 |
| 左格带头 | H3 做不到稳定去头（EV 2026-11-13 定：左格带头）。左格的脸小、细节易糊，以右格特写为准 |
| 背景 | 纯色**中性中灰**棚拍背景，三格一致 |
| 光 | 单侧柔和的定向棚拍光，阴影自然过渡 |
| 姿态 | 中性站姿，双臂自然垂在身侧。表情只在右格写一句中性的 |
| 一致性 | 写明"三格是同一个真人"，服装"三格一致" |
| 用词 | 用 "studio photographs / film character sheet"；**不写** "character reference sheet"、"painterly"（会滑向插画/概念设计） |

**辨识点插图**（EV 2026-11-13 定）：底档里有剧本给的辨识点（纹身、疤、胎记、痣）时，在整张图**左下角**加一张贴纸式小插图放这处特写，
带一圈细白边，叠在灰背景上，不挡左格的人。没有辨识点不加；这套衣服把辨识点盖住了（长袖遮住手臂纹身）也不加。

底档（长相）和服装（这一套）合在一起写进同一条提示词。

### 2. 场景 —— 完整的全景、空场景

| 项 | 规定 |
|---|---|
| 画幅 | 21:9（16MP：6272x2688） |
| 景别 | **全景**，一眼看全这个地方："a wide establishing shot that takes in the whole place"。写成"3/4 斜角、相机略高"会被画成高处往下拍的一块局部 |
| 机位 | 相机在**站立视线高度**，不俯拍。用简单的话，不写 CCTV、鱼眼这类术语 |
| 室外 | **必须有地平线和天空**，写明地平线在画面哪里（"the horizon runs across the upper third of the frame"） |
| 室内 | 斜着看过房间，同时看到两面墙和地面，主要陈设都入画。车内、电梯这类小空间不适用，看全整个座舱即可 |
| 人 | **空场景**，只写 "deserted, no one is there"。**不写** "empty / bare"（H3 会理解成没有东西，画出样板间） |
| 参照物 | 需求里那件"认得出的参照物"必须清楚地在画面里 |
| 氛围 | 一句氛围按官方规则落成看得见的细节（雾在哪、光从哪来），**前景保持清晰** |
| 光 | 场景里真实存在的光源和方向（窗光、灯、天光），不写笼统的"电影感光" |

H3 场景的毛病和写法：

- 爱把同类东西排成阵列。**不逐件写数量和位置去纠正** —— 写得越细越多，模型越把它当主角去堆，数量也不守。
  只写"有长椅"，加一句布局原则（像真实公园那样随意散布）
- 高度写数字或"齐腰高"它不听，用旁边的东西比："矮墙只到空调外机的一半高"
- 门外、窗外不写就是一片黑，写出外面是什么（灯亮着的走廊、院子里的路灯）
- 写进去的每一处缺陷都画得很显眼很刻意。缺陷写成整体程度（"years of ordinary wear"），点名的破损只留给剧情需要的
- 中式建筑光说名字结构会错（回廊画成两排柱子中间露天铺砖）。把结构写出来：一条带屋顶的廊，屋顶下是砖地，廊外一侧是水池

**不移植** lira-EV 的场景调色（褪色胶片、低对比、黑位提起、高光压暗、远景溶解、60/30/10 配色）：这些全局调色指令会让 H3 整张图发灰、过曝。

### 3. 道具 —— 产品照

| 项 | 规定 |
|---|---|
| 画幅 | 1:1（16MP：4096x4096）；细高的 3:4（3552x4736），扁长的 4:3（4736x3552） |
| 构图 | 3/4 俯拍的产品照，单独一件，完整入画，四周留白 |
| 背景 | 中性灰色哑光台面，干净无杂物。放不上桌的大件（车的外观、轿子、棺材）改成灰色棚拍地面 |
| 光 | 柔和的定向光，带一点自然投影，看得清材质 |
| 文字与标志 | 表面没有字和标志就正面写出来："plain unbranded surface"；再加无文字声明 |

一件道具的几种状态（完好 / 碎裂 / 激活发光）各出一张，不放在同一张图里。

### 4. 特效 —— 灰底上的孤立本体

特效指**独立的、能被释放出去的东西**（冲击波、传送门、地面光环、缠到别人身上的光索）。身上的光不是特效，画进角色图（分界见 ad-asset-bible）。
缠在人身上的特效（光索）也只画光本身的形态，不画人、不画人台 —— 视频模型会理解它缠在人身上。

| 项 | 规定 |
|---|---|
| 画幅 | 1:1（4096x4096）；竖着长的（光柱）3:4，横着铺开的（贴地光环）16:9 |
| 内容 | **只有特效本体**，居中、完整入画。没有人、没有手、没有身体，也没有地面以外的环境 |
| 背景 | 纯色**中性中灰**，跟角色三视图同一种灰。贴地的特效可以保留一块同色地面当落点 |
| 瞬间 | 凝固的一个瞬间，写它此刻的形态 |
| 用哪段 | 只用静态描述和设计；动态描述（`motion`）是给视频模型的，不进图片提示词 |

**要华丽，像电影特效，不像游戏贴图**（只写"一圈金色光环，往上冒光尘"出来一圈细光加一把均匀粒子，太游戏）。写进三样：

1. **层次**：核心一道白热的细线，外面一圈更宽的光带，光带上有流动的纹路
2. **跟空气和地面交互**：光在地面打出一片暖光、照亮贴地薄雾；光柱里的空气有热扭曲
3. **形态和颜色有变化**：拉长的火星、螺旋光带、大小不一的光点，越靠近源头越密越亮；颜色从白热过渡到浓色再到边缘的深色，跟冷灰背景拉开对比

开头写成 "A cinematic visual effects still from a high-budget fantasy feature film … photographed as if it were real light in real air"，不写 "magical effect" 这类泛称。

## 同一资产的多张图：用参考图，只编辑一次

同一个人的几套服装、一件资产的几种状态，各自从文字出图，模型没法知道是同一个（同一段长相描述、同一个种子，两张文生图的脸明显不是一个人）。
所以要拿**文生图出的原图**当参考出（编辑模式，按 `edit-en.txt` 写）。

**角色：先出一张脸图，所有服装和状态变体都拿它当参考。**

- 脸图是文生图，挂在角色底档的 tag 上：灰底头肩特写、3/4 侧脸看镜头、穿素色 T 恤，写进底档的脸、发型和辨识点；3:4，16MP 用 3552x4736。
  辨识点不在脸上（手臂纹身）时，取景放宽到胸口，把那只前臂抬进画面下沿、内侧朝镜头，让脸图里就有它，否则各套服装的辨识点插图只能凭文字各画各的。
- 出服装时提示词开头写明 "<Picture 1> 只提供长相，T 恤和构图不用"，三视图版面和这套服装照上面的写法完整写出来。
- **状态变体**（带伤、施法、淋雨）也拿脸图当参考（光在手上时，手可以在身侧微微翻开、掌心朝外），把"这套服装 + 这个状态"完整写进提示词，写到全身每个看得见的部位（脸、头发、手、鞋、头饰、衣服），不能只写衣服。
- **不拿一整张三视图（服装成图）当参考去换服装或改状态**：版面和服装会跟要改的内容打架（中格变正面、特写没换衣服），而且那是再编辑。
- 场景变体的 `refs` 指向的人如果 `sameFaceAs` 了别人，参考图用那个别人的脸图。
- 同一张脸的两个人（底档写了 `sameFaceAs`）只出一张脸图，两个人的服装都拿它当参考：`<Picture 1>` 只提供脸型和五官，
  发型、妆、肤色状态按这个人自己的设计写。

**场景：**

- **画面里有某人形象的场景**（遗照、雕像；副导演把形象登记在场景的变体上）：主资产是空着的底图，文生图
  （空相框、看不清脸的雕像）；带形象的变体拿底图 + 那个人的脸图两张当参考，编辑一次放上去；反打等其他变体也从底图编辑，
  画面里看得到那个形象的同样带上脸图。不拿已经放好形象的那张图再编辑。
- **衍生场景**（填了 `basedOn` 的：在主区域全景里看得见的区域，比如开放式的餐厅、厨房）拿主区域的全景文生图当参考出；
  它自己的变体（夜景、反打）**也拿那张全景图**，不拿衍生区域编辑出来的图。
- 没有 `basedOn` 的场景（同一栋楼里看不见的其他房间）各自文生图，风格靠设计稿 `_design` 里的共用约定。
- 场景变体拿主场景的文生图当参考。
- 场景画面里有某人的形象（场景的 `refs`：遗照、雕像、海报）时，把那个人的脸图也作为参考图带上，提示词里写明 `<Picture N>` 只提供这张脸、用在画面里的哪一处。

**道具**：状态变体拿主道具的文生图当参考；有 `refs` 的道具（照片、油画上画着某人某处）把被引用的那张图带上。

**只编辑一次。** 参考图必须是文生图出来的干净原图，不能拿编辑出来的图再去编辑；要改好几处就合成一条提示词一次改完。
每轮编辑都过一次 VAE 压缩和重画，上一轮的噪点被当成细节放大：实测同一张图连续编辑，第 2 次已经噪点大到不能用。
蒸馏版只能 6 步、CFG 1，没有参数能调。

**编辑时参考图和出图都用约 4MP，不用 16MP**（官方编辑工作流：参考图先缩到约 4MP、取 32 的倍数，出图尺寸照缩完的参考图）。
按 16MP 出，整张噪点重、要改的内容也改不上去；只缩参考图、出图仍 16MP，照样坏。
4MP 尺寸：16:9 2720x1536，3:4 1760x2336，4:3 2336x1760，1:1 2048x2048，21:9 3136x1344。

编辑出来的版面和细节偶尔跑偏（中格背面变正面、靴子款式变了），属于概率性的，换种子重出。

## 交出图单（接副导演的盘点时）

按 tag 交一份出图单 JSON，由副导演的 `scripts/attach-plan.mjs` 合进页面（命令见仓库根目录 `PIPELINE.md`）：

```json
{
  "_note": "整份出图单的通用说明，给手动出图的人看",
  "@char_lin": { "prompt": "…", "size": "3552x4736" },
  "@char_lin_suit": { "prompt": "The woman in <Picture 1> is …", "size": "2720x1536", "refImage": ["@char_lin"] }
}
```

- `size` 是这一张实际出图的像素，宽x高。编辑就写 4MP 那个尺寸。
- `refImage` 按 `<Picture 1>`、`<Picture 2>`… 的顺序写参考图的 tag，都指向文生图出的原图（脸图挂在底档 tag 上）。
- `_note` 照这段写："MiniMax H3-Image，官方工作流：6 步 / CFG 1 / euler / simple。文生图按标的尺寸出。编辑（带参考图的）：
  参考图先缩到约 400 万像素（16:9 约 2720x1536，3:4 约 1760x2336，4:3 约 2336x1760，1:1 约 2048x2048，21:9 约 3136x1344），输出按标的尺寸出；
  参考图必须是干净的文生图，不要拿编辑出来的图再编辑。"

出不出图看用户有没有通道。不要假设用户有哪台机器：

- **ComfyUI**（装了 H3-Image 的模型；本机要有 node 18+、ffmpeg 和 ffprobe）：用 `scripts/render-comfyui.mjs`，**分两段，中间让用户挑图**
  （EV 2026-11-15 定：编辑图都拿文生图当参考，底图不对，后面全白出）：
  1. `--stage t2i`：只出文生图，每张出 4 个候选（`--n` 改个数），生成 `<图片目录>/候选/挑图.html`。**出完停下**，把挑图网页给用户
  2. 用户在挑图网页里每个资产选一张、导出 `选择.json`（或在对话里说"公园选 3"，你写成 `{"@loc_gongyuan": 3}`）；
     `--pick 选择.json` 把选中的拷成正式的图。选 0 = 都不要：删掉候选，换个 `--seed` 再跑第 1 步重抽那几个
  3. `--stage edit`：出所有带参考图的，都拿选中的那张当参考，每张出一个
  按依赖顺序出、参考图自动缩到约 4MP、已出的跳过（断了重跑接着出）；模型文件名不同就加 `--unet / --clip / --vae`。
  编辑图单张重出：删掉那张，加 `--only <tag> --seed <新种子>` 再跑 `--stage edit`
- **MiniMax API**（有 `MINIMAX_API_KEY`）：`scripts/generate.py`，一张一张按依赖顺序发
- **都没有**：停在出图单

## 每类都要有的

- 结尾加无文字声明："The image contains no text, letters or numbers." 剧本写明画面里必须有的字（门上"手术中"的灯箱、
  招牌上的店名）例外：按官方规则用引号写出那几个字和位置，再声明 "No other text, letters or numbers appear.
- 写实质感用 "photorealistic"、"cinematic film still"、"studio photographs"。不写 "game"、"render"、"concept art"（写"游戏"会出游戏渲染风）。
- 少堆质感形容词：H3 会把"起球""毛孔"这类词放大成满身凸点、过锐的皮肤。
- 画幅与尺寸按上面的表，放在提示词外面交付（官方的 Output format 照旧）。
